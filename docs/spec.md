# Handoff hooks: behaviour contract

This is the behaviour contract the code-blind tests are written from: the tests are derived from this document, not from the code. Acceptance criteria (AC) numbers are stable; later sections amend earlier ones and say so. Paths are relative to this repository (`hooks/`, `install.sh`); the hooks install to `~/.claude/hooks/`. References to "the compact plugin" are to a separate optional Claude Code plugin that is not part of this repository.

Scope: `precompact-handoff.py` (PreCompact; its code is in the folder `hooks/lossless_handoff/`, see `docs/architecture.md`) and `postcompact-inject.py` (SessionStart, matcher `compact`).
Installed at `~/.claude/hooks/`; byte-identical repo copies in `hooks/`. Tests target either copy by path.
Freshness rule source of truth: the compact plugin spec F33.4 (restated in section 4 and AC 5-11).
This spec is written for a code-blind tester: it describes behaviour only.

**Named constant (single place to change if the directory moves):**
`HANDOFFS_DIR = $HOME/.local/state/claude-handoffs` (moved 2026-10-15: Claude Code denies model writes under `~/.claude/` as sensitive files; see the compact plugin spec F33.12). Every other mention of the handoffs directory in this document means `$HANDOFFS_DIR`; tests should define it once.

## 1. Purpose

Before Claude Code compacts a session, write a deterministic handoff file so the post-compaction session can recover its working state.
`precompact-handoff.py` writes it. `postcompact-inject.py` feeds `<sid>-latest.md` back as `additionalContext` on the post-compact SessionStart.
Both are best-effort and must never block or fail compaction: they always exit 0.

Registration (`~/.claude/settings.json`): `hooks.PreCompact[0].hooks[0]` = `python3 ~/.claude/hooks/precompact-handoff.py`, timeout 90 s.
`hooks.SessionStart[]` entry with `matcher: "compact"` = `python3 ~/.claude/hooks/postcompact-inject.py`, timeout 10 s.
(settings.json stores absolute paths; the repo copy stores `__HOME__`.)

## 2. Inputs

### 2.1 precompact-handoff.py
stdin: one JSON object. Fields used:
- `session_id` (string; default `"unknown"`; any `/` replaced with `_` for filenames)
- `cwd` (string; used for the git section and echoed in the header)
- `transcript_path` (string; JSONL file)
- `trigger` (echoed; if absent the header prints the literal `None`)

Env vars:
- `HOME`: root of everything. Output dir is `$HANDOFFS_DIR`.
- `HANDOFF_HOOK_CHILD`: if set to any non-empty value, exit 0 immediately and write nothing (recursion guard).
- `HANDOFF_HAIKU_FALLBACK`: exactly `"0"` disables the Haiku fallback. Any other value (or unset) leaves it enabled.
- `PATH`: used to resolve `claude` and `git`.

Files read:
- the transcript JSONL (tolerates missing file / bad lines)
- `<dir>/<sid>-agent.md` and `<dir>/<sid>-agent.meta.json` (agent-written handoff and its meta)

Transcript line format: one JSON object per line.
- `{"type":"user","message":{"content": <str | [blocks]>}, "isMeta"?: bool}`
- `{"type":"assistant","message":{"content": <str | [blocks]>}}` with blocks `{"type":"text","text":..}` and `{"type":"tool_use","name":..,"input":{..}}`.
- A user entry whose content list contains a `tool_result` block is ignored. `isMeta: true` entries are ignored.
- User text is "genuine" only if non-empty after strip and NOT starting with any of: `<task-notification`, `[SYSTEM NOTIFICATION`, `<system-reminder`, `<command-name`, `<local-command`, `<command-message`, `Caveat:`, `This session is being continued`.
- Tool uses: `Edit|Write|NotebookEdit|MultiEdit` give files (`file_path` or `notebook_path`; re-touching a file moves it to the end, no duplicates); `Bash` gives commands (`input.command`); `TaskCreate` creates task id `"1","2",...` (counter of TaskCreate calls) with status `pending` and `subject`; `TaskUpdate` (`taskId`, optional `subject`, optional `status`) updates or creates that id.

### 2.2 postcompact-inject.py
stdin: JSON object with `session_id`. Env: `HOME` only (via `~` expansion). File read: `$HANDOFFS_DIR/<sid>-latest.md`.

## 3. Outputs: precompact-handoff.py

stdout and stderr: always empty. Exit code: always 0.

Files written to `$HANDOFFS_DIR` (dir created if missing):
1. `<sid>-<YYYYMMDDTHHMMSSZ>.md` (UTC timestamp, second resolution)
2. `<sid>-latest.md`: byte-identical copy of (1).

If stdin has no usable `session_id`, `<sid>` is `unknown`.

### 3.1 File layout (headings in this order; any section may be absent)
```
# Handoff (pre-compaction)
- session: <sid>
- cwd: <cwd>
- trigger: <trigger>
- time: <YYYY-MM-DD HH:MM:SSZ>
- transcript: <transcript_path>
<blank line>
<LEAD, optional>
<sections joined by "\n", optional>
<blank line>
Full transcript: <transcript_path>. Read it for exact details before guessing.
```
LEAD, when non-empty, is one of the following (see section 4), followed by the line `## Facts (auto-extracted)` (the Facts line follows any non-empty lead, including the failure line):
- `## Agent handoff (written by the working agent)` + newline + agent body (stripped, max 5000 chars; truncated form ends in `...`), then a blank line
- `## Model-written handoff (Haiku fallback; verify against facts)` + newline + Haiku text (max 4000 chars), then a blank line
- a single line `Haiku fallback failed: <reason>`, then a blank line

Auto-extracted sections, in this order (each only when it has content):
1. `## Last user messages (oldest first)`: last 8 genuine user messages, each `- ` + text truncated to 600 chars with newlines replaced by spaces.
2. `## Files touched (last 30)`: `- <path>` for the last 30 distinct files, oldest first.
3. `## Task state`: `- [<status>] <subject truncated to 150>` per task in insertion order.
4. `## Git`: only if `cwd` is an existing dir inside a git work tree: `- branch: <branch>` then a fenced block of `git status --short` truncated to 1500 chars. Detached HEAD gives an empty branch.
5. `## Last Bash commands`: last 5 commands as ``- `cmd` `` (truncated to 200 chars, newlines to spaces).
6. `## Last assistant message`: last non-empty assistant text, truncated to 1500 chars.

`trunc(s,n)`: strip; if longer than n, first n-3 chars + `...`.

### 3.2 Char cap and trim order
Total file length is at most 9,500 chars (keeps SessionStart context under 10k). Header, LEAD and footer are never trimmed.
While over the cap, whole auto-extracted sections are dropped in this order: Last user messages, Files touched, Task state, Git, Last Bash commands, Last assistant message (so the last assistant message is the last to go). Sections are removed whole, never cut mid-section.

### 3.3 Degraded file
If building the body raises an unexpected exception, the file is instead:
```
# Handoff (pre-compaction, degraded)
- session: ..
- cwd: ..
- trigger: ..
- transcript: ..
- error: <repr(exception)>
```
and is still written to both paths. (Hard to provoke from outside; not covered by an AC.)

### 3.4 Cleanup
After writing, every `*.md` directly in the handoffs dir whose mtime is older than 14 days is deleted (this includes `*-agent.md` and `*-latest.md` of old sessions). Non-`.md` files (e.g. `*-agent.meta.json`, `*.txt`) and subdirectories are never deleted. The files just written are never deleted.

## 4. Lead selection: fresh vs stale vs no-meta vs fallback

`A = <dir>/<sid>-agent.md`, `M = <dir>/<sid>-agent.meta.json` (sid with `/` replaced by `_`).
A is FRESH when it exists, size >= 300 bytes, AND:
- M missing, unreadable, invalid JSON or not an object ("no meta"): mtime of A within the last 30 minutes (<= 30 min).
- M valid object: `agentWrittenAt` (number, not bool) present, AND either
  (a) `lastNudgeAt` is a number and `agentWrittenAt >= lastNudgeAt`, OR
  (b) `ctxTokens` and `agentWrittenAtTokens` are numbers and `ctxTokens - agentWrittenAtTokens <= 50000`.
  No `agentWrittenAt` means STALE. Non-number fields are treated as absent. mtime is ignored when meta is valid.
- Size < 300 bytes: STALE regardless of meta.

Decision:
1. FRESH: LEAD = Agent handoff section; Haiku is NOT invoked (even when fallback is enabled).
2. Not fresh and `HANDOFF_HAIKU_FALLBACK == "0"`: LEAD empty, and NO `## Facts (auto-extracted)` line is emitted.
3. Not fresh and fallback enabled: build an excerpt of the transcript (last 40 genuine user/assistant messages, each text truncated to 2500 chars, tool uses rendered `[tool <Name>: <key input truncated to 300>]`, whole excerpt cut to its last 30000 chars). If the excerpt is empty (missing/empty transcript) the result is failure reason `no transcript excerpt` and `claude` is not run. Otherwise run `claude` (resolved via `PATH`): argv starts `claude -p --model haiku --output-format text --no-session-persistence --setting-sources project --strict-mcp-config --mcp-config {"mcpServers":{}} --disable-slash-commands --tools ""`, the handoff prompt is the final argument, the excerpt goes on stdin; cwd = a fresh temp dir; env = parent env minus `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, plus `HANDOFF_HOOK_CHILD=1`; timeout 75 s.
   - exit 0 and stdout (stripped) >= 50 chars: LEAD = Model-written handoff section (text cut to 4000).
   - otherwise LEAD = `Haiku fallback failed: <reason>`, reason one of `claude exited <rc>`, `empty or too-short output`, `timeout after 75s`, `claude binary not found`, `no transcript excerpt`, or an exception class name.

## 5. Isolation for tests

- Overrides that exist: `HOME` (all paths derive from `~`; verified: with `HOME=<tmp>` the hook writes only under `<tmp>/.local/state/claude-handoffs/ (= HANDOFFS_DIR)`, and inject reads only from there), `HANDOFF_HAIKU_FALLBACK`, `HANDOFF_HOOK_CHILD`, `PATH`.
- There is NO env override for the handoffs dir, cap, freshness thresholds or timeout. They are constants. Tests must set `HOME` to a temp dir.
- Stubbing `claude`: it is invoked by bare name, so put an executable `claude` shim first on `PATH`. The shim gets the excerpt on stdin and the argv above; it can record them and print Haiku text. `git` is also resolved through `PATH`.
- Pass `HANDOFF_HAIKU_FALLBACK=0` in every test that is not about the fallback, so the real `claude` is never called.
- Time control: freshness uses real mtimes; set with `os.utime`. The 30-min rule and the 14-day cleanup are tested by setting mtimes, not by faking a clock. Meta freshness uses only meta numbers.
- Git section: needs `git` and a temp git repo as `cwd`.

### Testability gaps
- The `claude` path is not hard-coded (good), but the 75 s timeout cannot be shortened. Test the failure path with a shim exiting non-zero; a timeout test costs 75 s.
- Timestamped filenames have second resolution, so two runs in one second overwrite the same file. Sleep >= 1.1 s if two dumps are needed.
- `time:` header line is wall-clock: match with a regex.
- The degraded-file path (3.3) cannot be provoked from outside.

## 6. Outputs: postcompact-inject.py

Let `sid` = `session_id` (string) with every `/` replaced by `_` (the same rule precompact applies). If `sid` is non-empty and `$HANDOFFS_DIR/<sid>-latest.md` is a file, and its stripped content is non-empty, print exactly one line to stdout (`json.dumps` default separators):
```
{"hookSpecificOutput": {"hookEventName": "SessionStart", "additionalContext": "Pre-compaction handoff (auto-saved):\n<stripped file content>"}}
```
(Compare by parsing JSON; `\n` there is a real newline in the decoded string.) In every other case (missing file, empty file, bad JSON, bad/absent/empty session_id, non-dict JSON) print nothing. stderr always empty. Exit 0 always. No size cap of its own.

## 7. Error handling summary
- Malformed/empty stdin to precompact is treated as `{}`; the hook still writes `unknown-<ts>.md` and `unknown-latest.md` (`session: unknown`, empty transcript).
- Non-object JSON stdin (`[]`, `5`): same as `{}`.
- Unwritable handoffs dir or any I/O error: swallowed, exit 0.
- Transcript missing/unreadable, non-JSON lines, non-dict JSON lines, entries without `message`: skipped; extraction continues.
- `BaseException` is caught at top level; exit is always 0.

## 8. Acceptance criteria (temp `HOME`; `HANDOFF_HAIKU_FALLBACK=0` unless stated)

Exit / IO
1. For stdin = valid payload, `{}`, `[]`, `garbage`, empty string: exit code 0, stdout empty, stderr empty.
2. Valid payload with `session_id: "S"`: `S-latest.md` and exactly one `S-YYYYMMDDTHHMMSSZ.md` exist in `$HANDOFFS_DIR`, with identical bytes.
3. Garbage stdin writes `unknown-latest.md` containing `- session: unknown`.
4. `HANDOFF_HOOK_CHILD=1`: exit 0, `$HANDOFFS_DIR` is not created, nothing written. Same with fallback enabled.

Freshness
5. Agent file >= 300 bytes, no meta, mtime now, fallback enabled: output contains `## Agent handoff (written by the working agent)` followed by the body, then `## Facts (auto-extracted)`; the claude shim is NOT invoked.
6. No meta, mtime 29 min old: fresh; 31 min old: stale (no agent section).
7. 299-byte agent file with otherwise fresh meta: stale. 300 bytes: fresh.
8. Meta `{agentWrittenAt:100, lastNudgeAt:100}`: fresh. Meta `{agentWrittenAt:99,lastNudgeAt:100,ctxTokens:60000,agentWrittenAtTokens:10001}` (diff 49,999): fresh; diff exactly 50,000: fresh; `agentWrittenAtTokens:9999` (diff 50,001): stale.
9. Meta without `agentWrittenAt` is stale even if the file mtime is now.
10. Valid-but-stale meta with file mtime now: still stale (mtime ignored when meta is valid).
11. Invalid-JSON meta behaves as no meta (mtime rule).
12. Agent body longer than 5000 chars appears cut to 5000 chars ending `...`.

Haiku fallback
13. Stale/no agent file, fallback enabled, shim `claude` printing >= 50 chars: output has `## Model-written handoff (Haiku fallback; verify against facts)` and the shim text; the shim saw argv containing `-p`, `--model`, `haiku`, `--tools`; stdin containing `USER: <a user message>` from the transcript; env `HANDOFF_HOOK_CHILD=1`; and no `CLAUDE_CODE_AUTO_COMPACT_WINDOW` even if the test set it.
14. Shim exits 3: output contains `Haiku fallback failed: claude exited 3`. Shim prints < 50 chars: `Haiku fallback failed: empty or too-short output`. No `claude` on PATH: `Haiku fallback failed: claude binary not found`. Missing transcript: `Haiku fallback failed: no transcript excerpt` and the shim is not invoked. In each case `## Facts (auto-extracted)` follows.
15. Shim output over 4000 chars is truncated to 4000 chars.
16. `HANDOFF_HAIKU_FALLBACK=0` with stale agent file: shim never invoked; output has neither the Haiku heading, the failure line, nor `## Facts (auto-extracted)`. Values `1` and empty string still enable the fallback.
17. Fresh agent file with fallback enabled: shim never invoked.

Content and ordering
18. Header lines appear in order session, cwd, trigger, time, transcript; the last line is `Full transcript: <path>. Read it for exact details before guessing.`
19. A transcript with every content kind (>8 user messages, >30 files, tasks, git-repo cwd with dirty tree, >5 Bash commands, assistant text): headings appear in the exact order of 3.1 items 1-6. Only the last 8 users, last 30 files and last 5 commands appear; a file touched twice appears once at its latest position.
20. Two TaskCreate then TaskUpdate `taskId:"2" status:"completed"` yields `- [pending] <s1>` and `- [completed] <s2>`.
21. Messages starting with each noise prefix in 2.1, `isMeta` entries, and tool_result user entries never appear in the user list. The last non-empty assistant text is used.
22. cwd not a git repo or non-existent: no `## Git` section, exit 0.
23. Malformed transcript lines (invalid JSON, a JSON array, `{"type":"user"}` with no message) are skipped; valid lines around them are still extracted.
24. Over-cap: file length <= 9,500 chars; sections drop in the order Last user messages, Files touched, Task state, Git, Last Bash commands, Last assistant message; each remaining section is whole. With a fresh 5000-char agent body plus large sections, header, agent section and footer stay intact.
25. Under the cap, nothing is dropped.

Cleanup
26. A `*.md` with mtime 15 days old (e.g. `old-latest.md`, `x-agent.md`) is deleted; one 13 days old is kept; a 15-day-old `x-agent.meta.json` and `notes.txt` are kept; a 15-day-old directory named `d.md` is kept.

Inject
27. With `S-latest.md` non-empty: stdout parses as one JSON object equal to `{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"Pre-compaction handoff (auto-saved):\n"+<content stripped>}}`; exit 0.
28. Missing latest file, empty/whitespace-only file, `session_id` missing or empty, invalid JSON stdin: stdout empty, exit 0.
29. Sanitising parity (normative, ruled 2026-10-15): for `session_id` `a/b`, precompact writes `a_b-latest.md` and inject given `{"session_id":"a/b"}` outputs that file's content (not nothing). Known to FAIL against current code (inject skips ids containing `/`); the code is to be fixed.
30. End to end: additionalContext produced from a hook-written file has length < 10,000.

## 9. Rulings and notes
- Sanitising: ruled a bug in inject; fixed by AC 29 (same `/` to `_` rule in both hooks).
- Cleanup deleting old `*-agent.md` is intended (documented in 3.4).
- Header prints literal `trigger: None` when `trigger` is absent (cosmetic).
- The 14-day cleanup also removes old `<sid>-agent.md` files (the model-written ones), since it globs all `*.md`; intended (ruled). Meta `.json` files are never cleaned, so they accumulate.
- If header + lead + footer alone exceed 9,500 chars (very long paths) the cap cannot be honoured.
- With fallback enabled and no shim, a real `claude -p` runs in tests (up to 75 s).

## F35 additions (2026-10-16)
Draft for approval. Why: see the compact plugin spec "F35 Handoff quality". These additions amend sections 2.1, 3.1, 3.2 and 4 of this contract; where a statement here conflicts with an earlier AC, the F35 statement wins and the amended earlier ACs are listed in AC 46. Code touched (for the builder): `hooks/precompact-handoff.py` `parse()` (:39), `is_fresh()` (:134), `read_agent()` (:150), `lead_section()` (:238), `build()` (:251). `postcompact-inject.py` is unchanged.

### F35.A Inputs added
- Transcript entries may carry `"timestamp"` (ISO-8601 UTC string, e.g. `2026-10-16T10:32:05.123Z`). `lastUser` = the timestamp of the last GENUINE user message (same filter as 2.1) that has a parseable timestamp, in epoch ms. No such entry: `lastUser` is absent and the grace rule is skipped.
- Meta (`<sid>-agent.meta.json`) optional fields written by the compact plugin (compact.md F35.1): `sections` (heading name to 12-hex hash), `prevSections`, `stale_sections` (array of strings), `lastNudgeAt`, `lastUserMsgAt`. Non-array `stale_sections` and non-string members are treated as absent.
- Section hash: first 12 hex chars of SHA-256 of the section body (bytes after the heading line up to the next line starting `## ` or EOF, trailing whitespace stripped, `\r\n` as `\n`). Headings recognised: the six exact lines `## Goal`, `## Decisions and why`, `## Done`, `## In progress`, `## Dead ends`, `## Exact next step`.
- Tool results: a user entry whose `message.content` list holds a `tool_result` block with `tool_use_id` is read ONLY for the three F35 extractions below; it is still excluded from "Last user messages".

### F35.B Freshness v2 and staleness (supersedes the Decision in section 4)
Constants: `FRESH_GRACE_MS = 600000`, `STALE_USER_TURNS = 3`, `STALE_TOOL_CALLS = 40`.
`present` = the agent file exists and size >= 300 bytes. `fresh` = `present` AND the section-4 rule holds AND (`lastUser` absent OR file mtime ms >= `lastUser` - 600000) AND `stale_sections` (meta) is empty or absent AND NOT `hookStale`. `hookStale` = meta has `sections` AND the current hashes of "In progress" and "Exact next step" both equal the meta `sections` values AND, counting transcript entries whose timestamp is later than meta `lastNudgeAt`, genuine user messages >= 3 OR assistant `tool_use` blocks >= 40 (entries without timestamps are not counted; no `sections` or no `lastNudgeAt`: `hookStale` false).
Staleness reasons, in this order, joined with `; `: (a) meta `stale_sections` non-empty, or `hookStale`: `<names joined with ", "> unchanged since <T>` where names are `In progress, Exact next step` and `<T>` = UTC `YYYY-MM-DD HH:MM:SSZ` of meta `lastNudgeAt` (if absent, of the file mtime); (b) grace failed: `file written <T> is older than the last user message by more than 10 min` with `<T>` = file mtime UTC; (c) section-4 rule failed while `present`: `not updated since the last nudge`.
Decision (replaces section 4 steps 1-3):
1. Not `present` (missing, unreadable, < 300 bytes): as old steps 2 and 3 (no agent section; Haiku per `HANDOFF_HAIKU_FALLBACK`).
2. `present` and `fresh`: LEAD = Agent handoff section only; Haiku NOT invoked (unchanged).
3. `present` and not `fresh`: LEAD = the warning line `Agent handoff may be stale: <reasons>`, then the heading `## Agent handoff (written by the working agent)` and the agent body (stripped, max 5000 chars, `...` form as before), then a blank line, then, unless `HANDOFF_HAIKU_FALLBACK` is exactly `0`, the Haiku section or `Haiku fallback failed: <reason>` line exactly as section 4 (agent first, Haiku below). Then `## Facts (auto-extracted)`. The warning line is a bare line (no `#`), directly above the agent heading, no blank line between.
Byte layout of a stale lead: `Agent handoff may be stale: ...\n## Agent handoff (written by the working agent)\n<body>\n\n## Model-written handoff (Haiku fallback; verify against facts)\n<text>\n\n## Facts (auto-extracted)\n`.

### F35.C Cap (supersedes 3.2 for the lead)
Cap stays 9,500. Header, warning line, agent section and footer are never trimmed (agent body already <= 5000). When the total is over the cap because of the Haiku text, FIRST shorten the Haiku text (cut to fit, ending `...`); if less than 200 chars of it would remain, omit the whole Haiku section (the `Haiku fallback failed:` line, being short, is kept). Only then drop auto-extracted sections by the order in F35.D.

### F35.D Facts dump additions
New sections, with the final order in 3.1: 1 Last user messages, 2 `## Decisions via questions`, 3 Files touched, 4 Task state, 5 `## Open tasks`, 6 `## Background agents`, 7 Git, 8 Last Bash commands, 9 Last assistant message. Each only when non-empty. Drop order when over the cap (supersedes 3.2): Last user messages, Files touched, Task state, Git, Last Bash commands, Last assistant message, Background agents, Open tasks, Decisions via questions (the new three are the last to go, the question answers first of all being kept). No redaction exists in the current dump; the new sections add none and carry only the fields below (no message bodies, no tool inputs beyond them), each cut with `trunc` and newlines turned into spaces.
- `## Decisions via questions`: pair each assistant `tool_use` named `AskUserQuestion` (`input.questions[]` with `question`, optional `header`, `options[].label`) with the answer in the later user entry whose `tool_result.tool_use_id` matches. Answer source, in order: the entry's `toolUseResult.answers` map (question text to chosen label string; multi-select answers are the labels joined with `, `); else the result text pattern `"<question>"="<answer>"` repeated. Notes: `toolUseResult.annotations[<question>].notes` if present. A question with no answer (tool_result error, rejection, or missing) is skipped. Keep the LAST 10 pairs in transcript order, oldest first. Line: `- [<header>] <question> -> <answer>` with ` (notes: <notes>)` appended when notes exist; `[<header>] ` omitted when no header; question, answer and notes each `trunc(.., 200)`.
- `## Open tasks`: the latest task state with status != `completed`. Two sources, listed in this order: (i) `TaskCreate`/`TaskUpdate` state exactly as the existing `## Task state` builds it; (ii) `TodoWrite`, where the last `TodoWrite` call's `input.todos[]` (`content`, `status`) replaces all earlier TodoWrite state. Line `- [<status>] <subject-or-content trunc 150>`; statuses shown verbatim (`pending`, `in_progress`). Max 20 lines, then `- ... +<n> more`. `## Task state` is unchanged (it lists all tasks incl. completed).
- `## Background agents`: assistant `tool_use` named `Agent` (or `Task` when `input.subagent_type` is present) with `input.run_in_background` true. Its id = `agentId: <id>` (or `agent_id: <id>`) in the matching `tool_result` text; no id found: unfinished by definition until a notification names its `description`. Finished when a later user entry whose text starts `<task-notification` contains that id (or, with no id, the description string). Unfinished ones, in transcript order, max 10: `- <description trunc 100> (model: <input.model or "default">)`. No prompt text, no subagent_type, no ids.

## F36 Handoff reliability (2026-10-16)

### F36.B Health log (1.a)
Every PreCompact run (every run that is not a `HANDOFF_HOOK_CHILD` run) appends exactly ONE JSON object, one line, to `HEALTH_FILE`, even when the hook failed at top level, and also when stdin was garbage. Fields (all always present, in this order; `json.dumps` default separators):
`ts` (UTC `YYYY-MM-DDTHH:MM:SSZ`), `sid` (first 8 chars of the sanitised session id; `unknown` when absent), `trigger` (`auto` | `manual`; absent or unrecognised is recorded as the string `unknown`), `agent_file` (`absent` | `fresh` | `stale`; `absent` = not `present` per F35.B, `stale` = present but not fresh), `stale_sections` (array of the heading names that caused staleness reason (a) of F35.B, `[]` otherwise), `fallback` (`skipped` = agent file fresh so Haiku not wanted | `ok` | `failed` | `timeout` | `disabled` = `HANDOFF_HAIKU_FALLBACK` is `0`), `duration_ms` (integer, whole hook, monotonic clock), `output_chars` (integer, length of the `latest.md` content written; 0 if none written), `truncated` (bool, true when the cap of 3.2/F35.C removed or shortened anything), `errors` (array of section names that raised, in assembly order, plus `toplevel` if F36.C applied; `[]` if none), `status` (`ok` | `reduced` | `degraded`, defined in F36.D), `hook_version`, `canary_child` (bool, always present, default false).
Rulings: `fallback: timeout` iff the fallback reason is `timeout after 75s`; every other fallback failure reason is `failed`. A stale agent file with fallback `0` is `agent_file: stale, fallback: disabled`. No agent file and fallback `0`: `absent`/`disabled`.
The line carries NO message text, no paths, no cwd, no transcript content, no exception messages (types only, and only inside the handoff itself, never in the health line).
Rotation: after appending, if the file has more than 5000 lines, rewrite it to its last 5000 lines (write a temp file in the same dir, then atomic rename). Rotation failure is swallowed and never loses the just-appended line. A health write failure (unwritable dir) is swallowed; exit stays 0 (it cannot be reported from the hook; the sidecar and canary are the detectors).
Sidecar: the hook ALSO writes `$HANDOFFS_DIR/<sid>-last-health.json` (full sanitised sid): the same object plus `reasons` (array of reason codes, F36.D; for `reduced` it holds the informational code `agent_absent` or `agent_stale`, for `ok` it is `[]`) and `degraded` (bool, true iff `status` is `degraded`), overwritten on every run. This is the only channel `postcompact-inject.py` reads.

### F36.C Fail-safe assembly (1.b)
1. Each output section is built by its own function inside its own `try/except Exception`. A raising section is replaced IN PLACE by exactly one line `(section <name> unavailable: <ExceptionType>)` (`<ExceptionType>` = `type(e).__name__`, never the message) and its name is appended to `errors`. Placement: the replacement line sits where the section's heading would have been; for `warning` it sits directly above the agent heading; for `agent` it replaces the agent section (and Haiku still runs per F35.B as if the file were not present... if the agent builder raised, `agent_file` is recorded from the freshness decision made before the raise, default `absent`).
2. The replacement line counts toward the 9,500 cap but is never itself dropped by cap trimming; a section replaced by this line is not a candidate for trimming.
3. The hook always emits whatever succeeded and exits 0 with empty stdout/stderr (AC 1 unchanged). Header and footer are built from the stdin fields with no section logic and cannot be skipped.
4. Top-level failure: any exception outside the section functions (parse of stdin aside, which already degrades to `{}`) or a `BaseException` during assembly writes, instead of the normal file, the MINIMAL HANDOFF (to both `<sid>-latest.md` and the timestamped file, as usual):
```
# Handoff (minimal: hook failed with <ExceptionType>)
- session: <sid>
- cwd: <cwd>
- trigger: <trigger>
- time: <UTC ts>
- transcript: <path>
- git branch: <branch>          <- line omitted if `git -C <cwd> rev-parse --abbrev-ref HEAD` fails, git is missing, or cwd is not a repo
Full transcript: <path>. Read it for exact details before guessing.
```
   The minimal builder uses only string formatting and a single guarded `git` call (5 s timeout) and has its own `try/except`; if even it fails, the hook writes the single line `# Handoff unavailable (hook failed)` plus `- session: <sid>`. In all top-level cases `errors` contains `toplevel`, `agent_file`/`fallback` are recorded as known at failure time (defaults `absent`/`skipped`).
5. Order of effects: write handoff files first, then the sidecar, then the health line (last, in a `finally`), so a crash in logging cannot lose the handoff.

### F36.D Degraded flag and injection (1.c)
Reason codes (closed set) and their human text used in the warning line, in this order:
`agent_absent` -> `no agent handoff`, `agent_stale` -> `agent handoff stale`, `fallback_failed` -> `Haiku fallback failed`, `fallback_timeout` -> `Haiku fallback timed out`, `section_errors` -> `sections unavailable: <names joined ", ">` (names from `errors`, including `toplevel`), `no_health` -> `no health record for this compaction`, `handoff_missing` -> `no handoff file for this session`, `handoff_old` -> `handoff not refreshed for this compaction`.
**Status (computed by the hook; decided by the user 2026-10-16, replacing the earlier "absent agent file is always degraded" ruling).** Three levels, evaluated in this order:
1. `degraded` iff ANY of: `errors` non-empty (any section error or `toplevel`); `stale_sections` non-empty; `agent_file != fresh` AND `fallback in (failed, timeout, disabled)` (no fresh agent file and no working Haiku summary).
2. else `reduced` iff `agent_file != fresh` AND `fallback == ok` (no fresh agent file, but the Haiku fallback succeeded and nothing raised). Reduced is expected in sessions without the compact plugin's nudge; the Haiku summary is the designed fallback, so it is logged and counted but never alerted.
3. else `ok` (`agent_file == fresh`, `errors` empty).
`reasons` (codes in the order above): for `degraded`, every code that applies (`agent_absent` when `agent_file` is `absent`, `agent_stale` when `agent_file` is `stale` or `stale_sections` is non-empty, `fallback_failed`, `fallback_timeout`, `section_errors`); for `reduced`, exactly `agent_absent` or `agent_stale` (informational, never shown to the model or the user); for `ok`, `[]`. A `disabled` fallback adds no code of its own (the text for `agent_absent` already says there is no agent handoff). Missing or old handoff and missing health record are detected at inject time (`handoff_missing`, `no_health`, `handoff_old` below) and are `degraded`.
Injection by status: `ok` and `reduced` inject exactly the section 6 string with NO prefix and NO neutral note (decision: a note would cost context tokens on every reduced compaction, which is routine, and would train the model to ignore the prefix; the health log and weekly report carry the information). Only `degraded` adds the warning line.

`postcompact-inject.py` (extends section 6):
- Let `S` = `<sid>-last-health.json` and `L` = `<sid>-latest.md`.
- Normal: `L` non-empty and `S` readable valid object with `ts` within the last 15 minutes and `degraded` false (`status` `ok` or `reduced`): output exactly as section 6 (AC 27), no prefix, no note. No `-degraded.json` is written (an existing one is left untouched).
- Degraded: `S.degraded` true: `additionalContext` = `HANDOFF DEGRADED: <human texts joined "; ">. Verify the handoff against the transcript before acting.\n` + the section 6 string (`Pre-compaction handoff (auto-saved):\n<content>`). The warning is the FIRST line of `additionalContext`. And it writes `<sid>-degraded.json` = `{"v":1,"sid":"<sid>","ts":"<now UTC>","reasons":[<codes>],"trigger":"<S.trigger>","detected_by":"inject"}` (atomic: temp + rename; overwrite). An existing file for an earlier compaction is overwritten and loses any `clearedAt`.
- Silent-failure cases, all treated as degraded with a minimal injection: `L` missing/empty/unreadable -> reason `handoff_missing`, `additionalContext` = `HANDOFF DEGRADED: no handoff file for this session. Read the transcript (see session metadata) before acting.`; `L` present but `S` missing/unreadable/invalid -> `no_health` and `L` still injected below the warning; `S.ts` older than 15 min or unparseable -> `handoff_old` and `L` injected below the warning (it may belong to an earlier compaction). In these cases `-degraded.json` is written with the code(s). Session id missing/empty/non-string stays silent: no output, no file (nothing to key on).
- Healthy path unchanged: stdout one JSON line or nothing, stderr empty, exit 0 always. Any exception while computing degradation falls back to the section 6 behaviour for `L` and, if that is also impossible, prints nothing.
- Size: the warning line counts toward the same < 10,000 bound as AC 30 (the file is capped 9,500; warning <= 300 chars; total < 10,000).
Cleanup (amends 3.4): after writing, `*-degraded.json` and `*-last-health.json` directly in the dir older than 14 days are deleted; `health.jsonl` is never deleted by cleanup (it rotates by F36.B); other non-`.md` files keep the 3.4 rule.

Purpose: prove nightly, with a real headless Claude Code session, that PreCompact fires, a handoff is written, SessionStart(compact) injects it, and the resumed model acts on it. Location: the canary tool (not part of this repository) (`run.sh` orchestrator; `check.py` pure checker; `fixtures/`). The phrase "`hooks/handoff-canary.sh`" in the request is satisfied by a thin `hooks/handoff-canary.sh` that just `exec`s the canary runner.

**Schedule.** the canary LaunchAgent template, label `com.lossless-handoff.handoff-canary`, `StartCalendarInterval` `{Hour:3, Minute:30}` (daily, no Weekday key), `RunAtLoad` true with `--catch-up` semantics (run only if `last-run.json` is absent or older than the most recent 03:30; a no-op otherwise), `ProgramArguments` `/bin/bash -lc '<hooks>/handoff-canary.sh --catch-up'` (`<hooks>` = the installed hooks dir; the wrapper `handoff-canary.sh` execs `<hooks>/handoff-canary/run.sh` with the same arguments, or `../tools/handoff-canary/run.sh` in a repo checkout, and exits 2 with a message when neither exists), logs to `__HOME__/.local/state/handoff-canary/logs/launchd.{out,err}`, `EnvironmentVariables` = `HOME` and `PATH` per the shared LaunchAgent environment rule. `install.sh --canary` writes the plist to `$HOME/Library/LaunchAgents/` on macOS (and loads it unless `LOSSLESS_HANDOFF_NO_LAUNCHCTL=1`), or prints a crontab line on Linux; `uninstall.sh` removes it; `plutil -lint` must pass. State dir `~/.local/state/handoff-canary/` (mode 700): `last-run.json`, `runs/<ts>/` (kept 14 days), `logs/`.

**Isolation (hard).** Every canary session: cwd = a fresh `mktemp -d` project containing only `.claude/settings.json` that registers exactly the two handoff hooks (absolute repo paths, same timeouts as the template: PreCompact 90 s, SessionStart `compact` 10 s) and no other hooks; invoked with `--setting-sources project` so user settings/hooks are not loaded, `--strict-mcp-config --mcp-config '{"mcpServers":{}}'`, `--disable-slash-commands`, `--model haiku`, `--output-format json`, `--permission-mode acceptEdits`, `--allowedTools "Read Write Edit Bash"` limited by a `Bash` allow-list prefix of the temp dir only where the CLI supports it. Env: `HANDOFF_STATE_DIR=<tmp>/handoffs` (so hooks write only there), `HANDOFF_CANARY=1`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW=<W>`, `HOME` unchanged (auth needs it). The canary never reads or writes any real project, the real handoffs dir, or the vault. Session ids are fresh UUIDs passed with `--session-id`. A run aborts (result `fail`, reason `isolation`) if the temp dir is not under `$TMPDIR` or any hook line appears in the REAL `health.jsonl` with `canary_child` true. User-level `~/.claude/CLAUDE.md` is NOT loaded under `--setting-sources project` (verified 2026-10-16); the checks below are token-based anyway. Every `claude` invocation redirects stdin from `/dev/null` (`-p` otherwise waits 3 s for stdin).

**Forcing compaction (the choice).** Primary: AUTO compaction by a small window. `W = 60000` (default; env `HANDOFF_CANARY_WINDOW` overrides; values below 40000 are rejected with exit 2 because the CLI does not honour them, see Verified). Justification: 60,000 is the value the existing F35.7 manual E2E already uses; the measured isolated baseline context is about 30.1k tokens, so 60000 leaves about 30k of headroom, reached in 2-3 padding reads. Each padding file is deterministic text the canary generates (never real data), about 9k tokens, and MUST be multi-line (for example up to 2000 lines): the Read tool truncates at about 42k characters per line, so a single-line file cannot be paged. The session is driven as a chain of non-interactive turns: turn 1 `claude -p --session-id <uuid> ...`, later turns `claude -p --resume <uuid> ...` (one process per turn; each turn's JSON gives `total_cost_usd` and `session_id`). Padding turns use `--allowedTools Read` with `--permission-mode acceptEdits` (verified to work). Compaction is expected inside the 2nd-3rd padding read; the driver reads the PreCompact health line to detect it (a new line in `<tmp>/handoffs/health.jsonl`) and stops padding. Cap: at most 12 turns per compaction attempt; if no PreCompact line appears, the variant FAILS with reason `no_compaction` (this itself is a valuable signal: auto-compaction not triggering in `-p`). Fallback driver, used only if the primary fails: `claude -p --resume <uuid> "/compact"`, verified to run a manual compaction under `-p` and to fire PreCompact with `trigger: manual` and SessionStart `compact` (the canary's own sessions use `--disable-slash-commands`, so the fallback driver omits that flag for that turn only). The post-compaction answer is always requested on the turn IMMEDIATELY after the compaction: the injected context of an earlier compaction is not repeated after a second compaction (verified), which is also why `HANDOFF_CANARY_DOUBLE=1` checks the token only after the last compaction. Each variant forces compaction exactly once; "twice" in the request = once per variant, in two separate sessions (A then B), so each hook path is exercised and a single compaction per session keeps cost low. (A run MAY do a second compaction in the same session when `HANDOFF_CANARY_DOUBLE=1`, to cover the `latest.md` overwrite case; default off.)

**Scripted task.** Fixture-driven and deterministic: the canary generates a random 10-hex run token `R` per run. Task prompt (turn 1): "You are running a canary. Do these steps in order, one per turn, in this directory: step 1 create s1.txt containing ONE; step 2 create s2.txt containing TWO; step 3 create s3.txt containing THREE; final step 4 create done.txt containing the text `<TOKEN_X>`. - Variant A (agent file present): `TOKEN_X = A-<R>`. After step 2 and before padding, the canary itself writes `<tmp>/handoffs/<sid>-agent.md` (>= 300 bytes, six headings, "Exact next step" = `create done.txt containing A-<R>`) and a matching `<sid>-agent.meta.json` (`agentWrittenAt` = now, `lastNudgeAt` = 1 s earlier, so FRESH by F35.B). - Variant B (agent file absent -> fallback): `TOKEN_X = B-<R>`, stated in turn 1 (so it is in the transcript the Haiku fallback summarises). No agent file is created. Expected health line: `agent_file: absent`, `fallback: ok`, `errors: []`, `status: reduced` (reason `agent_absent`, informational); no degraded file and no warning in the injected context (expected, not a failure). The canary therefore exercises the `ok` and `reduced` paths; the `degraded` inject path is covered by fixtures (ACs 62-65).
Post-compaction turn (both): `claude -p --resume <uuid> "State your exact next step, in one line, quoting the text to write in done.txt. Do not do it."`.

**Checks (pure function `check.py`, fixture-testable).** Variant passes iff ALL hold: (1) a health line exists in `<tmp>/handoffs/health.jsonl` with `trigger` `auto` (or `manual` when the `/compact` driver is used) and `canary_child` true; (2) the line matches the expected `agent_file`/`fallback`/`errors`/`status` for the variant (A: fresh/skipped/[]/ok; B: absent/ok/[]/reduced); (3) `<sid>-latest.md` exists and contains `TOKEN_X` (A: inside `## Agent handoff`; B: anywhere, expected inside the Haiku section or Facts); (4) the SessionStart hook ran and injected without a warning: `<sid>-degraded.json` absent for BOTH variants (A is `ok`, B is `reduced`) and the health line `status` is `ok` (A) / `reduced` (B); (5) the answer of the turn immediately after the compaction (from the JSON `result`) contains `TOKEN_X` as a substring (case-sensitive) AND does not contain the other variant's token; (6) no `Haiku fallback failed:` line in `latest.md` (B); (7) total elapsed under the timeout; (8) cost under the cap. Variant A check (5) is the strong one: the token is only reachable through the injected handoff. Variant B check (5) can also be satisfied by the compaction summary alone, so (3) and (6) carry the Haiku path's proof. A failed check records the FIRST failing check number as `reason` (`c1`..`c8`, or `no_compaction`, `timeout`, `claude_missing`, `isolation`, `cost_cap`, `error`).

**Limits.** Hard wall-clock timeout 12 minutes per run (watchdog started with the orchestrator; implemented without GNU `timeout`, using a background `sleep`+`kill` of the process group, because macOS lacks `timeout`), 5 minutes per `claude` turn. Expected cost (measured 2026-10-16): about $0.02-0.05 per session (a 7-turn session with 2 compactions ended at $0.030), so about $0.04-0.10 per nightly run. `claude` not on PATH or not logged in: result `skip` (reason `claude_missing`), NOT pass and NOT fail; skips are shown in the report. **Output.** Appends one line to the REAL `$HOME/.local/state/claude-handoffs/health.jsonl` (via the same append+rotation code path semantics as F36.B; the canary writes it itself): `{"ts","sid":"<first 8 of variant A session id>","trigger":"canary","result":"pass"|"fail"|"skip","reason":null|"<code>","variants":{"A":"pass|fail","B":"pass|fail"},"duration_ms","est_cost_usd","hook_version":"<from the hook lines seen, else null>","canary_child":false}`. Same field set rules otherwise as far as applicable (the compaction-only fields `agent_file`, `fallback`, `stale_sections`, `output_chars`, `truncated`, `errors` are absent on canary lines, readers must key on `trigger`). ## F44 Recall: exact words after compaction (approved in design by the user 2026-11-13, inspired by "LCM: Lossless Context Management", arXiv 2605.04050)
Why: summaries and the ledger keep decisions, but exact details (commands, numbers, paths, the user's wording) are lost at compaction. Claude Code already keeps every message verbatim in `~/.claude/projects/<slug>/<sid>.jsonl` (LCM's "immutable store"); what is missing is LCM's retrieval side (`lcm_grep`/`lcm_expand`). The user chose: scope = all chats in the same project; form = a local command plus one line in the injected context (no MCP server, ~0 tokens until used); use = rule-based. Not adopted from LCM: replacing Claude Code's context assembly (no hook can), the summary DAG, a database.

**F44.1 Command.** New file `hooks/recall.py` (installed to `~/.claude/hooks/recall.py`, Python 3 stdlib only; uses `rg` when on PATH, else a pure-Python scan with identical output). Read-only except its own cache. Subcommands (all accept `--cwd DIR`, default the process cwd):
- `search <pattern> [--fixed] [--role user|assistant|tool|any] [--session SID8|all] [--limit N] [--subagents]`: case-insensitive regex (or fixed string with `--fixed`) over message text. Default role `any`, session `all`, limit 20 (max 100). Output one hit per line, newest first: `<sid8>:<line> <YYYY-MM-DD HH:MM> <role>: <snippet>` where snippet is the match with up to 120 chars each side, newlines shown as ` / `. Final line `<k> hits shown of <m> (<s> sessions searched)`.
- `open <sid8>:<line> [--around K] [--full]`: prints the message at that transcript line plus K (default 2, max 10) messages before and after in the same session, each headed `--- <sid8>:<line> <ts> <role>`; each message body capped at 4,000 chars unless `--full` (cap 40,000) with `[cut: <n> more chars]`.
- `user [--last N] [--session SID8|all]`: the user's own typed messages verbatim, newest first, default 20 (max 200), same heading form.
- `handoffs`: list this project's handoff files in `<state>` (`<sid>-latest.md`, `<sid>-agent.md`, timestamped dumps) whose `cwd` line is inside the project root, newest first: `<mtime> <path> <bytes>`.
Every subcommand caps total stdout at 12,000 chars (then prints `[output cut at 12,000 chars; narrow the search]`). Exit 0 on success including zero hits; exit 2 on bad arguments or unknown id.

**F44.2 Project scope.** Project root = git toplevel of `--cwd` (else `--cwd` itself), same key as F39.1. Sessions in scope: main transcripts `~/.claude/projects/*/<sid>.jsonl` whose first record carrying `cwd` has a realpath equal to or inside the root (a slug-prefix shortcut may pre-select directories but the `cwd` check decides). Subagent transcripts (`<sid>/subagents/*.jsonl`, or records with `isSidechain: true`) only with `--subagents`. A cache `<state>/recall-index.json` maps transcript path -> {mtime, size, cwd} so unchanged files are not re-read for scoping.

**F44.3 What counts as a message.** Records with `type` `user` or `assistant`. Role `user` = user records whose content is typed text (string or text blocks), excluding tool results, `isMeta` records, command/caveat wrappers and compaction summaries (`isCompactSummary`); `<system-reminder>…</system-reminder>` blocks and hook-injected `additionalContext` are stripped before matching. Role `assistant` = assistant text blocks (not thinking). Role `tool` = tool_use inputs and tool_result text. A line that fails JSON parsing is skipped silently.

**F44.4 Redaction.** Before printing, replace with `[redacted]`: strings matching `sk-[A-Za-z0-9_-]{16,}`, `ghp_[A-Za-z0-9]{20,}`, `github_pat_[A-Za-z0-9_]{20,}`, `AKIA[0-9A-Z]{16}`, `xox[abp]-[A-Za-z0-9-]{10,}`, and the value after `password=`/`token=`/`secret=` up to whitespace. Matching runs on the unredacted text.

**F44.5 Speed.** On a project with 3.6 GB of transcripts, `search` with a literal word returns in under 10 s on the user's machine with `rg` (prefilter with `rg -n` then parse only matching lines). No index of message text is built.

**F44.9 Meaning search (hybrid; approved by the user 2026-11-13).** recall also finds messages by meaning, using a local embedding model, and merges that with keyword hits.
- Backend: Ollama at `RECALL_EMBED_URL` (default `http://localhost:11434`), model `RECALL_EMBED_MODEL` (default `bge-m3`), request `POST <url>/api/embed` with `{"model": m, "input": [texts]}` -> `{"embeddings": [[floats]]}`. `RECALL_EMBED_BACKEND=openai` switches to `POST <url>/v1/embeddings` (`{"model","input"}` -> `{"data":[{"embedding":[...]}]}`) with optional `RECALL_EMBED_KEY` as a Bearer token. Timeouts: 5 s for a query, 60 s per index batch. Stdlib only (urllib, sqlite3, array, math).
- Index: `<state>/recall/<project-key>.sqlite` (project key as F39.1). Indexed units: role `user` and `assistant` messages (F44.3; never tool text, never subagents), split into chunks of at most 1,500 chars on paragraph or sentence boundaries; chunks under 20 chars skipped; text is redacted (F44.4) BEFORE embedding. Rows: sid, line, chunk, ts, role, unit-normalised float32 vector. A per-transcript byte offset makes indexing incremental (only new lines); a model change (name or dimension) rebuilds the index.
- `recall.py index [--cwd DIR] [--max-seconds N]`: indexes new messages for the project in batches of 32, prints progress `indexed <n> chunks, <k> remaining`, stops cleanly at `--max-seconds` (default none). Takes a lock file `<state>/recall/<project-key>.lock` (a second runner exits 0 at once with `index busy`). Exit 0 also when the backend is unreachable (prints `meaning index skipped: <reason>`).
- `search` modes: default hybrid; `--keyword` = F44.1 only; `--meaning` = embedding only. Hybrid: keyword hits (up to 200, F44.1 rules) and the top 50 chunks by cosine similarity are merged with reciprocal-rank fusion (k = 60, equal weights); a message found by both counts once. Each hit line gains a source tag after the role: `[word]`, `[meaning]` or `[both]`. In meaning/hybrid mode the query is also embedded as plain text (a query that is not a valid regex is used as a fixed string for the keyword part instead of exiting 2). The first output line states the mode: `mode: hybrid (meaning index covers <i> of <n> messages)` or `mode: keyword only (meaning search off: <reason>)`; the search then proceeds keyword-only. Same 12,000-char cap.
- Keeping the index fresh: the PreCompact hook starts `recall.py index --cwd <cwd> --max-seconds 600` fully detached (no wait, output to `<state>/recall/index.log`) after it has written the handoff; it never delays or fails the hook. The installer prints the one-time command to build the first index.
- Speed: hybrid search on a 50,000-chunk index answers in under 10 s without numpy (vectors stored normalised; dot products in pure Python over `array('f')`).
- The F44.6 line is unchanged except `search "<regex>"` becomes `search "<words or regex>"`.

## F46 Subagent isolation and always-on hooks (user decision 2026-11-17: "whatever context needs to be injected has to be the sub-agent's context and not the main agent's"; "make sure it always loads")
Why, from a live probe on Claude Code 2.1.325 and the hooks docs:
- When a SUBAGENT compacts, PreCompact, SessionStart (`source` compact) and PostCompact fire with `agent_id` and `agent_type` set, but `session_id` and `transcript_path` are the PARENT's. The subagent's own transcript is `<dirname(transcript_path)>/<session_id>/subagents/agent-<agent_id>.jsonl` (its `compact_boundary` records carry `isSidechain: true`, `agentId`). The main transcript has no boundary for it. For a main-agent compaction `agent_id` is absent.
- SessionStart additionalContext printed for a subagent's compaction lands in that subagent's context only (the main agent does not see it).
- Every compaction also emits a SubagentStop for an internal summariser fork: fresh `agent_id`, `agent_type` "" (empty), no SubagentStart.
- Today (1.9.0): PreCompact sees `agent_id` and takes the F42.5 subagent path (health line only, no handoff), and `postcompact-inject.py` ignores `agent_id`, so a compacting subagent is given the MAIN session's handoff (and, with F45, could trigger a recovery that rewrites the main handoff from a subagent event). Both are wrong.
- Headless: `claude -p` and the Agent SDK load user hooks by default. They are skipped with `--bare` (skips settings hooks), `disableAllHooks`, `--setting-sources` without `user`, or SDK `settingSources: []`. Managed settings (`/Library/Application Support/ClaudeCode/managed-settings.json` on macOS) load in every case, including the SDK, and lower levels cannot disable them; `--bare` behaviour for managed hooks is unconfirmed. Identical hook commands defined in two settings levels are run once (verify in the manual acceptance).
- (a) Agent identity. A hook input with a non-empty `agent_id` is a subagent event. Its key is `<sid>-a-<agent_id>` (sid as used today for file names) and its transcript is the derived subagent path above. Every file a main run writes per session (handoff archive and latest, pending, last-health sidecar, degraded marker, agent note) has a per-agent twin under that key. Main-session files are never read or written by a subagent event, and subagent files are never read for a main event.
- (b) PreCompact for a subagent replaces the F42.5 health-only path: it runs the same pipeline as a main compaction (pending file, write-early, agent note if `<key>-agent.md` exists, fresh summary, size caps) over the SUBAGENT transcript, keyed by `<key>`, and appends a health row with `sid` (the PARENT's sid, same format as main rows), `agent_id`, `agent_type` and the normal fields (ruling 2026-11-17: rows are matched by sid plus `agent_id`). It does NOT merge the project decisions ledger (subagents follow the ledger; only the main session updates it) and does not start the indexer. If the derived transcript does not exist, it writes a health row with status `degraded`, reason `agent_transcript_missing`, and writes no handoff.
- (c) SessionStart `compact` for a subagent: parts 1-3 inject the subagent's own handoff (`<key>` files) with the same rendering, warnings and F45 recovery (recovery reads the subagent transcript and writes `<key>` files and a `recovered` row with `agent_id`). The ledger parts are injected as for the main agent (project rules apply to subagents). The main session's handoff is never injected into a subagent. `startup`/`resume` (no `agent_id`) are unchanged.
- (d) Reconcile (F45 c) also reads `<project folder>/<session>/subagents/agent-*.jsonl`: boundaries there count per (session, agent_id), matched to health rows with that `agent_id`; it reports `subagent compactions <n> · missed <m>` as a second line and lists missed ones as `missed <count> <sid8> agent <agent_id> <project folder> <ts>`. Main-session counting is unchanged (rows with an `agent_id` never count as main handoffs). The F45 AC 177 fixture's subagent file uses this layout from now on; AC 177's first line is unchanged.
- (e) Compaction forks. Any hook code that reacts to SubagentStop or SubagentStart ignores events whose `agent_type` is empty.
- (f) Handoff nudge (the compact plugin, F33): a nudge for a model request that belongs to a subagent never names the main `<sid>-agent.md`. If the plugin API exposes the subagent's id and context size for that request, it nudges that subagent with its own threshold and file `<sid>-a-<agent_id>-agent.md`; otherwise it does not nudge subagents. Main-loop behaviour is unchanged. Plugin version bump (minor). Standalone behaviour (this repository, `hooks/handoff-nudge.py`): a PostToolUse input carrying a non-empty `agent_id` is ignored entirely: no note, no read or write of `<sid>-agent.meta.json`. Only main-loop events nudge.
- (g) Always on. `install.sh --managed-hooks` is a standalone mode: it does only this step and exits (no repos, plugins, brew, network or other bootstrap steps; under 5 s). It writes `<state>/managed-settings.json`: the current system file's content if one exists (read-only access), merged with the handoff hook entries from the settings entries (PreCompact, SessionStart compact/startup/resume, SessionEnd), nothing else added, and prints the one command for the user to run: `sudo install -m 644 <that file> "/Library/Application Support/ClaudeCode/managed-settings.json"`. On Linux it prints `/etc/claude-code/managed-settings.json` instead. The README documents: headless jobs keep hooks unless started with `--bare`, `disableAllHooks`, `--setting-sources` without `user`, or SDK `settingSources: []`; with managed hooks only `--bare` can skip them; reconcile reports any compaction that still got no handoff.

## F54 Summary nodes (2026-11-18)
Why: the LCM paper keeps a DAG of summary nodes, each with an id and a link to the messages it covers (`lcm_describe`, grep grouped by node). Here, after many compactions, the model sees only the newest handoff and a flat search: it has no map of the session and no way from a summary back to its messages. Claude Code's transcripts already hold every needed fact (`compact_boundary` records and the `isCompactSummary` record), so leaf nodes need no model call.

**F54.a Store.** Each project ledger folder (the folder that holds `decisions.md`) gets `nodes.jsonl`, one JSON object per line, append only. A leaf node has:
- `id`: `n` + the first 10 hex characters of sha1(`<session id>:<boundary uuid>`). Stable: the same boundary always gives the same id.
- `kind`: `"leaf"`.
- `session`: the session id. `agent`: the subagent id, or `null` for the main chat. `transcript`: the absolute transcript path.
- `seq`: 1 for the first `compact_boundary` in that transcript, 2 for the second, and so on.
- `boundary_uuid`, `time` (the boundary record's timestamp), `trigger`, `pre_tokens` (from `compactMetadata`, `null` if missing).
- `first_line`, `last_line`: the 1-based transcript line range this node covers: from the line after the previous boundary (line 1 for `seq` 1) to the line before this boundary.
- `prev`: the id of the leaf with `seq - 1` in the same transcript, or `null`.
- `handoff`: the path of the handoff file written for this compaction if one exists, else `null`.
Ids are unique in the file. A malformed line is skipped by readers and never crashes them.

**F54.b Sync.** One function syncs a transcript: it reads the transcript from the byte offset it reached last time (kept in `nodes.state.json` next to `nodes.jsonl`), and appends a node for each new `compact_boundary`. It holds the same kind of lock as the ledger writes. If a transcript got shorter or was replaced, it rescans that transcript from the start and adds only missing ids. It runs:
1. In the SessionStart `compact` hook, for the session's own transcript (the agent's own transcript for a subagent), before the output is built. A sync error never changes the rest of the hook's output and never gives a non-zero exit.
2. In `recall.py map`, `describe`, `search --node`, for every transcript of the project (main chats and their `subagents/agent-*.jsonl`).
3. In `recall.py nodes --backfill`, for every transcript of the project. It prints `nodes: <added> added, <total> total`.

**F54.c Commands.**
- `recall.py map [--session S|all] [--limit N]` (default all, 200): one line per leaf, grouped by session, oldest first:
  `<id> <time YYYY-MM-DD HH:MM> <session8>[/<agent8>] #<seq> lines <first>-<last> <pre_tokens> tokens: <gist>`
  The gist is the first 160 characters (whitespace collapsed) of the node's Claude Code summary section whose heading contains `Current Work`; if there is none, of the summary text after its first line. No summary found: gist `(no summary)`. The last line is `<n> nodes in <k> sessions`. No nodes: `no summary nodes yet`, exit 0.
- `recall.py describe <id>`: the node's fields one per line (`id:`, `session:`, `agent:`, `seq:`, `time:`, `lines:`, `pre_tokens:`, `prev:`, `handoff:`), then `open: python3 ~/.claude/hooks/recall.py open <session8>:<first_line>`, then a blank line and the full Claude Code summary text for that boundary (the `isCompactSummary` record that follows it; cut by the normal output cap). Unknown id: `no node <id>`, exit 1.
- `recall.py search ... --node <id>`: only hits whose transcript is the node's transcript and whose line is in `first_line`..`last_line`. Unknown id: `no node <id>`, exit 1.
- Every `search` hit line (word, meaning or hybrid) ends with ` [node <id>]` when the hit's transcript line falls in a leaf's range, and ` [node live]` when it is after the transcript's last boundary.

**F54.d Inject.** If the sync found a leaf for the boundary of this compaction, the SessionStart `compact` output gets one more line right after the recall line:
`- summary node: this chat continues after node <id> (compaction #<seq>, lines <first>-<last>). See all nodes: python3 ~/.claude/hooks/recall.py map; one node: recall.py describe <id>.`
No leaf found: no line. The `startup` and `resume` sources do not get it.

**F54.e Proof.** `--prove --days N` gets a `nodes` check over the transcripts in the window, after a sync: every `compact_boundary` has exactly one leaf; in each transcript the leaf ranges do not overlap, start at line 1, and leave no gap up to the last boundary. The check covers every transcript (main and subagent) under `~/.claude/projects` that has at least one `compact_boundary` with a timestamp in the last N days. It does not depend on receipts or on an earlier SessionStart sync, because `--prove` runs the sync itself first. It prints `nodes: <b> boundaries, <n> leaves, <bad> bad` and counts as failed when `bad` > 0.

## F62 Nudge window source (2026-11-19)
Why: an independent review found that the nudge assumed a 400,000-token window when `CLAUDE_CODE_AUTO_COMPACT_WINDOW` is unset. With a 200,000-token model the first reminder (300,000) is above the real compaction point, so the nudge never fires. The window differs for each user, so the hook calculates it from real compactions and does not hard-code it.

**F62.a Order.** The nudge hook (`hooks/handoff-nudge.py`) picks the window in this order:
1. If `CLAUDE_CODE_AUTO_COMPACT_WINDOW` is a positive integer, use it. This is today's behaviour, unchanged. Source: `env`.
2. Else learn it from real compactions. Take the pre-compaction token counts of the newest `compact_boundary` records (up to 20) in the current transcript. Skip a record whose `compactMetadata.trigger` is `manual`; keep a record with no trigger. The count is the field `compactMetadata.preTokens` (the same field that the summary nodes of `recall.py` store as `pre_tokens`). If the current transcript has none, take them from the other transcripts of the same project folder (`~/.claude/projects/<slug>/*.jsonl`, newest files first, at most 5 files, read-only, stop at 20 counts). If at least 1 count exists, window = median of the counts + 33,000, rounded to the nearest 1,000. If the result is below 100,000 or above 2,100,000, it is not used and step 3 applies. The scan has a time budget of 1.5 s: after that, use the counts found so far (at least 1), else step 3. A sibling file that cannot be read is skipped. Source: `learned`.
3. Else use 200,000. Source: `default`.

**F62.b Thresholds.** All thresholds derive from the chosen window with the existing formulas: the first reminder at 75% of the window, then every 25,000 tokens, and the final nudge at window minus 45,000. **F62.c Record.** The hook writes the chosen window and its source to `<sid>-agent.meta.json` as `window` (integer) and `windowSource` (`env`, `learned` or `default`). The PreCompact health row in `health.jsonl` holds them as `window` (integer) and `window_source` when that meta file exists (the nudge hook writes no health row of its own). The hook keeps a `learned` or `default` value in the meta for 6 hours, and re-computes it after a compaction (context shrank), so a scan of a large transcript does not run on every tool call.

**F62.d Nudge tag.** The nudge text starts with `[lossless-handoff] This note comes from the lossless-handoff PostToolUse hook that the user installed in ~/.claude/settings.json.` (before 0.12.2: `[claude-handoff]` and `claude-handoff PostToolUse hook`).

## F65 Redaction (2026-11-19)

**F65 (redaction).** One shared function (`redact()` in `hooks/recall.py`) masks secrets before text is written to: the PreCompact handoff files (deterministic part and fresh summary), the latest and dated handoff copies that the hooks write, the decisions list (and its backups), and recall output. Each match becomes `[REDACTED:<kind>]`:

- `aws`: `AKIA` or `ASIA` and 16 characters.
- `github`: `ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `github_pat_`.
- `slack`: `xox[abprs]-`.
- `anthropic`: `sk-ant-...`. `openai`: `sk-...`.
- `google`: `AIza` and 35 characters.
- `jwt`: three base64url parts, the first starts with `eyJ`.
- `pem`: `-----BEGIN ... PRIVATE KEY-----` to `-----END ... PRIVATE KEY-----`.
- `url`: the password in `scheme://user:password@host`.
- `secret`: the value after `Authorization: Bearer`, and `key=value` or `key: value` where the key name ends with `password`, `passwd`, `passphrase`, `secret`, `secret_key`, `token`, `api_key`, `apikey`, `access_key` or `private_key`. A value after `Bearer` is masked. A quoted value is masked inside its quotes. The key stays.
- F65.a A prefix (`sk-`, `sk-ant-`, `gh?_`, `github_pat_`, `xox?-`, `AKIA`, `ASIA`, `AIza`, `eyJ`) matches only when no letter, digit, `_` or `-` comes before it. `tests/task-runner-suite.py` stays unchanged; `key=sk-...` and `"sk-proj-..."` are masked.
- F65.b A `secret` value is masked only when it has 8 or more characters, is not only letters, is not only digits, and is not a call, an index or a placeholder (a name after a dollar sign, a name in braces after a dollar sign, a letters-only name in angle brackets, or a name in double braces). A value that starts with a dollar sign but has other characters, such as `password=$uperS3cret!!`, is masked. A value in angle brackets with digits, such as `token=<abc12345XYZ>`, is masked. The value must start on the same line as the key. `token: 160000 of 400000`, `if not token: return None`, `api_key: str = Field(...)`, `Set HANDOFF_SECRET=0` and `secret = get_secret(name)` stay unchanged.
- F65.c The time to redact a text is linear: `"a." * 20000` and 200,000 base64url characters take under 1 second.

Text without secrets stays byte-identical. The function is idempotent. The hooks never write the unmasked value to a state file. The model writes its own agent handoff file with the Write tool and a hook cannot mask that write; this limit is documented, and every copy that a hook makes of it is masked. This amends F44.4 and ACs 143 and 152: the mark is now `[REDACTED:<kind>]` instead of `[redacted]`, and the patterns are the ones above. The nightly proof treats both marks as redacted.

## F67 Auto-recall (opt-in) (2026-11-20)

Why: Claude often answers from its own memory (possibly lost in the middle, or compacted) instead of searching. Claude Code writes every message to the transcript file as the chat goes on, so the live context is searchable too. Auto-recall runs the search for Claude when the prompt refers to the past, and puts the exact quotes at the end of the context.

**F67.a Install.** New hook file `hooks/auto-recall.py`, registered as a `UserPromptSubmit` command hook `python3 <hooks dir>/auto-recall.py` with timeout 5 seconds.
- Opt-in: `install.sh --auto-recall` installs and registers it. A default install does not install or register it.
- `--save-defaults` writes `auto_recall=1` when `--auto-recall` is given. `--no-auto-recall` turns a saved default off for one run. `--save-defaults --no-auto-recall` removes the line. F64 holds: a re-install never removes it. For an installed copy the installer prints `auto-recall: already installed, kept`.
- `uninstall.sh` removes the file and its `settings.json` entry. `--dry-run` lists it. The settings edit keeps a backup, like the other hooks.
- `HANDOFF_AUTO_RECALL=0` makes the hook print nothing and exit 0.

**F67.b Trigger.** The hook reads the hook JSON on stdin (`prompt`, `transcript_path`, `cwd`, `session_id`). It fires only if all of these hold: the prompt does not start with `/`; and the prompt matches a cue (case does not matter). A cue is one of these phrases: `what did i say`, `what did you say`, `what did we decide`, `did we decide`, `did we agree`, `did i say`, `did i tell you`, `we decided`, `we agreed`, `i told you`, `i said`, `you said`, `you mentioned`, `i mentioned`, `last time`, `previously`, `as we discussed`, `as discussed`, `which one did`, `earlier you`, `earlier i`, `earlier we`, `said earlier`, `said before`, `as before`, `like before`, `same as before`, `do you remember`, `remember when`, `remember what`; or a double-quoted phrase of 3 or more words. A phrase matches as whole words, and case does not matter. The bare words `before`, `earlier`, `remember`, `did i`, `did we` and `what was the` are not cues: "run the tests before you commit" gives no output. Otherwise: no output, exit 0.

**F67.c Search and output.**
- Query: the prompt with the cue phrases removed, then the 8 longest remaining words of 4 or more characters. If fewer than 2 such words remain: no output, exit 0. A double-quoted phrase is also searched as an exact phrase.
- Scope: the transcripts of the current project (the scope of `recall.py search`), main chats and subagents. The current prompt is excluded. Mode: word and meaning if the meaning index exists, else word only. The word part matches whole words. Only user and assistant messages are shown; tool calls and tool results are left out (they are removed before the cut to the best hits). For speed, the hook lists only the project folders in `~/.claude/projects/` whose name starts with the encoded project root (every character that is not a letter or digit becomes `-`), plus the folder of the current transcript. The scope code of `recall.py` still decides by the working directory inside each transcript. The current prompt is excluded only when the hit is in the file of `transcript_path`; a newline in the prompt is compared as a space.
- The top 3 hits. Each snippet: spaces collapsed, at most 300 characters, passed through `redact()` (F65).
- Output on stdout, exactly: line 1 `Lossless Handoff auto-recall: earlier messages that match your words. Verify them before you rely on them.`; then one line per hit `- <id> <YYYY-MM-DD HH:MM> <role>: <snippet>` (id and role as `recall.py search` prints them); last line `Open one in full: python3 ~/.claude/hooks/recall.py open <id>`.
- No hits: no output, exit 0. A missing or incomplete `recall.py`: no output, exit 0.
- Time budget: 2.0 seconds for the whole hook. If the search is not done in time, no output, exit 0. The hook never fails a prompt: every error gives no output and exit 0.

**F67.d Health.** Each run that passes the trigger appends one JSON line to `~/.local/state/claude-handoffs/auto-recall.jsonl`: `{"ts", "session_id", "fired": true, "cue": <the matched phrase from the list, or "quote">, "hits": <n>, "ms": <int>, "timed_out": <bool>}`. The `cue` value is always a fixed list phrase or `quote`, never prompt text. No prompt text and no snippets are in this log.

**F67.e Versions.** Product 0.15.0 (`install.sh`). `HOOK_VERSION` is `1.17.0` in every hook that has it, `auto-recall.py` too. This amends the version value in ACs 136, 150, 172, 180, 188 and 267 again.

## F68 Strict recall rules (opt-in) (2026-11-22)

Why: the model can skip a recall search when it is wrongly sure. One short rule line next to the recall line makes a search more likely. It does not force one.

**F68.a Install.** Flag `--recall-rules`, saved key `recall_rules`, name `recall-rules`. Install writes the marker file `<hooks dir>/.recall-rules`. Uninstall removes it. F64 holds: `--save-defaults` writes `recall_rules=1`; `--no-recall-rules` turns a saved default off for one run; `--save-defaults --no-recall-rules` removes the line; a re-install never removes an installed marker and prints `recall-rules: already installed, kept`; `--dry-run` lists it; a default install does not write it.

**F68.b Rule line.** When the marker exists and `HANDOFF_RECALL_RULES` is not `0`, every place that injects the recall line (SessionStart `compact`, `startup` and `resume` output, and the SubagentStart output) adds this exact line directly after the recall line: `- recall rule: before you state an earlier number, path, name, command or decision, search for it. Do not answer from memory. If the search finds nothing, say so.` With no marker, or with `HANDOFF_RECALL_RULES=0`, the output is byte-identical to 0.15.0 (when recall-mcp is not installed). A summary node line, if present, follows the rule line.

**F68.c Health.** The inject row in `receipts.jsonl` has `"recall_rules": true|false`.

## F69 Recall MCP tool (opt-in) (2026-11-22)

Why: a tool in the tool list is easier for the model to use than a shell command that it must remember.

**F69.a Install.** Flag `--recall-mcp`, saved key `recall_mcp`, name `recall-mcp`, same F64 rules as F68.a (the kept message is `recall-mcp: already installed, kept`). Install copies `hooks/recall-mcp.py` (it is in the manifest) and runs `claude mcp add --scope user lossless-recall -- python3 <hooks dir>/recall-mcp.py`. If `claude` is not on the PATH, install prints `recall-mcp: claude CLI not found; register it later with: claude mcp add --scope user lossless-recall -- python3 <hooks dir>/recall-mcp.py`, still installs the file and exits 0. If the add command fails (for example the server is registered already), install prints one line with the command and exits 0. `--dry-run` lists the file and the command and runs nothing. Uninstall runs `claude mcp remove lossless-recall --scope user` when `recall-mcp.py` is installed (a failure is ignored) and removes the file. No code edits `~/.claude.json` directly.

**F69.b Server.** Stdlib-only MCP server over stdio: newline-delimited JSON-RPC 2.0 with `initialize`, `notifications/initialized`, `ping`, `tools/list` and `tools/call`. Server name `lossless-recall`, version `HOOK_VERSION`. The `initialize` reply echoes the `protocolVersion` of the client when it is one of `2025-11-25`, `2025-06-18`, `2025-03-26` or `2024-11-05`, and else gives `2025-06-18`. The `instructions` text (under 4,096 characters) holds the F68 rule sentence and one line on when to use the tools. A malformed JSON line gets a JSON-RPC error `-32700` and the server goes on. An unknown method gets `-32601` and an unknown tool name `-32602`. A notification gets no reply.

**F69.c Tools.** Each tool has `_meta: {"anthropic/alwaysLoad": true}`. `search_earlier_chat`: `{query: string (required), role?: "user"|"assistant"|"any" (default "any"), limit?: integer 1-10 (default 5)}`. It calls the search code of `recall.py` (loaded by path) for the project of the server working directory: same scope and ranking as `recall.py search` (word, and meaning when the index exists). Output: one line for each hit in the `recall.py search` hit format, through `redact()`. No hits: `no matches`. `open_message`: `{id: string (required), full?: boolean (default false)}`. Output: the same text as `recall.py open <id>` (with `--full` when `full` is true), through `redact()`. A result has at most 12,000 characters; a longer result is cut so that the total, including the cut marker, is at most 12,000 characters, and its last line is `[cut at 12000 characters]`. A bad input or an unknown id gives a tool result with `isError: true` and one line of text.

**F69.d Recall line.** When `recall-mcp.py` is installed, the injected recall line ends with ` Or call the search_earlier_chat tool.` (after the recall subagent sentence, when that is present).

**F69.e Health.** Each tool call appends `{"ts", "tool", "hits", "ms"}` to `recall-mcp.jsonl` in the state folder (`HANDOFF_STATE_DIR` is honoured). No query text.

**F69.f Neither F68 nor F69 forces a search.** The model decides. This is stated in `docs/recall.md` and `docs/limitations.md`.

**F69.g Versions.** Product 0.16.0 (`install.sh`). `HOOK_VERSION` is `1.18.0` in every hook that has it, `recall-mcp.py` too (this holds for F68 to F71). This amends the version value in ACs 136, 150, 172, 180, 188 and 267 again.

## F70 Re-anchor (opt-in) (2026-11-22)

**F70 (re-anchor).** Why: in a long context the model gives less weight to the standing rules that sit far back. Re-anchor repeats them near the end. It follows the F64 rules for opt-in parts.

- F70.a Install: `./install.sh --reanchor` (saved key `reanchor`; `--no-reanchor`; `--save-defaults --no-reanchor` removes the line). It copies `hooks/reanchor.py` (in the manifest) and registers a `PostToolUse` entry, matcher `*`, timeout 5. A re-install never removes it and prints `reanchor: already installed, kept`. `--dry-run` lists it. `uninstall.sh` removes the file and the entry.
- F70.b Count: the hook reads the context token count as `handoff-nudge.py` does (the usage of the last assistant entry: input + cache read + cache creation), from the end of the transcript only (64 KB, then 400 KB). It keeps its own copy of these few lines because `handoff-nudge.py` is optional (`--no-nudge`) and importing it would cost start time. A subagent event (non-empty `agent_id`) is ignored.
- F70.c Anchor: state in `reanchor-<session>.json` (`{"v":1,"anchor":<int>}`, default 0). A count below the anchor means a compaction: the anchor becomes the current count and nothing is printed. A count of the anchor plus the interval or more triggers an injection. The interval is 50,000, or `HANDOFF_REANCHOR_TOKENS` when it is an integer from 10,000 to 500,000. The new anchor is stored before the text is built, also when there is no rule, so the rules builder runs at most once per interval.
- F70.d Output: exactly one JSON object `{"hookSpecificOutput": {"hookEventName": "PostToolUse", "additionalContext": <text>}}` (this is the shape in the Claude Code hooks reference for PostToolUse). The text is the first line `Lossless Handoff re-anchor: the project's active rules, repeated so they stay near the end of your context.`, then the rules block of the SubagentStart hook (at most 4,000 characters, F58/F66.b, with the recall line at its end). The block comes from `postcompact-inject.py --rules-block` (new mode: stdin `{"cwd"}`, prints the text, nothing when there is no active rule, no health row). No active rule: no output.
- F70.e Off and errors: `HANDOFF_REANCHOR=0` prints nothing. Every error prints nothing and exits 0.
- F70.f Health: one row per injection in `health.jsonl`: `{"ts","session_id","event":"reanchor","tokens":<int>,"chars":<int>}`.
- F70.g Speed (measured on a 35 MB transcript): no-op path p50 20.0 ms, p95 22.3 ms (bare `python3 -c pass`: 11.3 ms); inject path p50 58.2 ms, p95 58.9 ms.
- F70.h Version: `HOOK_VERSION = "1.18.0"`.

## F71 Claim guard (opt-in, shadow by default) (2026-11-22)

**F71 (claim guard).** Why: the model sometimes states an earlier fact from memory ("as we decided ...") without searching. The guard finds those replies.

- F71.a Install: `./install.sh --claim-guard` (saved key `claim_guard`; `--no-claim-guard`). It copies `hooks/claim-guard.py` and registers a `Stop` entry, timeout 5. Re-install, dry-run and uninstall follow F70.a (`claim-guard: already installed, kept`).
- F71.b Input: the hook JSON with `session_id`, `transcript_path`, `stop_hook_active` and `last_assistant_message`. If `stop_hook_active` is true: nothing. In live mode there is at most one block per user turn (`claim-guard-<session>.json` holds the uuid of the last user message that was blocked).
- F71.c Cue: whole words, case-insensitive: `as we decided`, `we decided`, `as you said`, `you said`, `we agreed`, `as agreed`, `as discussed`, `you told me`, `you mentioned`, `as mentioned earlier`, `earlier you`, `last time`. The first cue of this list that matches is logged.
- F71.d Evidence: since the last real user message (type `user`, not a tool result, not meta), any of (a) a Bash tool call whose command contains `recall.py`, (b) a tool call whose name starts with `mcp__lossless-recall__`, (c) an entry whose text starts with `Lossless Handoff auto-recall:` (the header of `hooks/auto-recall.py`; the 5 entries before the user message are also checked, because the position of an injection entry is not documented). With evidence: nothing.
- F71.e Modes: `HANDOFF_CLAIM_GUARD` unset or `shadow`: one row `{"ts","session_id","would_block":true,"cue"}` in `claim-guard.jsonl`, no output. `block`: the same row, and the Stop output below. `0`: nothing. No reply text or prompt text is ever logged. Every error prints nothing and exits 0.
- F71.f Live output form. The hook prints `{"decision": "block", "reason": "You stated an earlier fact without searching. Search for it with recall, then correct or confirm it."}`. The hooks reference (Stop decision control) says: "`decision` | `"block"` prevents Claude from stopping" and "`reason` | Required when `decision` is `"block"`. Tells Claude why it should continue". We chose this form because it is the documented, long-standing form that carries a `reason`, and a claim without evidence is a fault that the user should see in the transcript. The other documented form, `hookSpecificOutput.additionalContext` with `hookEventName` `Stop`, is meant for "non-error feedback" and shows as "Stop hook feedback"; it is the fallback if the block form is removed. Both forms use the same loop limits: "the `stop_hook_active` input and the 8-consecutive-continuation cap" (quoted from the same page, 2026-11-22). The hook honours `stop_hook_active` and the once-per-turn rule.
- F71.g Version: `HOOK_VERSION = "1.18.0"`.

## F72 Hooks-folder override (2026-11-22)

Why: a benchmark arm runs a private copy of the hooks. It must not read the live install of the user, and a live install during a run must not change an arm.

**F72.a Override.** `HANDOFF_HOOKS_HOME` covers only the lookups of other installed files: `recall.py`, the marker `.recall-rules`, `recall-mcp.py` and `postcompact-inject.py`. When it names an existing folder, a hook looks for those files there instead of in `~/.claude/hooks`. If it is unset, empty or not a folder, the folder is `~/.claude/hooks`, as before. The lookups are in `auto-recall.py`, `postcompact-inject.py` (including the recovery call of `precompact-handoff.py` and `--check`), `recall-mcp.py`, `reanchor.py`, and the `lossless_handoff` parts `summary.py` and `prove.py` (for `recall.py`). `claim-guard.py` and `recall.py` look up no file in the hooks folder.

**F72.b No mixing.** When the override is set to a folder, a hook never falls back to `~/.claude/hooks` for those files, and it does not use a copy next to the hook file either. A missing file in the override folder means the part is absent (for example no recall line). The own parts of a hook (`lossless_handoff/*.py`, and any helper that the entry file loads from beside itself) always load from beside the entry file that runs. The override does not change that.

**F72.c Amendment of F69.** The limit of 12,000 characters per tool result includes the cut marker (see F69.c).
