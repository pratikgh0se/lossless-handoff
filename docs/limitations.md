# Limitations

The full list of limits. This page is part of the [docs index](README.md).

- **One heavy user so far.** All numbers come from the author's machine. Nobody has tested whether it helps other workflows.
- **Handoffs can be cut.** Main chats: 27% of handoffs (75 of 283, 2026-10-16 to 2026-11-25, `health.jsonl`) hit the 14,000-character size cap and were truncated. Subagents: 0 of 42 (2026-11-17 to 2026-11-24). Only the auto-extracted fact sections are cut first. The `reduced` and `degraded` shares and the nightly self-test failed 2 of 34 runs (31 passed and 1 was skipped; see "In daily use").
- **Recall is new.** It has existed since 2026-11-12. The author did most of its use so far, much of it while the author built and tested it. The meaning half is a minority of wins (4 of 26 searches had a meaning-only top hit). The 143 meaning hits count lines shown, not proof that they were useful.
- **Misses still happen.** 4 of 192 main compactions in the 30-day reconcile had no handoff (see [Proof, not promises](evidence.md#live-checks-the-proof-run)). The early write, recovery and `--check` exist to make the misses fewer and to show them. They do not promise zero. Receipts exist only from the first compaction after install, so proof rates start small. C7 and C8 are dated one-off studies, not live rates.
- **Redaction is pattern-based.** The hooks mask known secret shapes (AWS, GitHub, Slack, Anthropic and OpenAI style keys, Google API keys, JWTs, PEM private keys, passwords in URLs (kind `url`), `Authorization: Bearer` values, and the values of keys that end with `password`, `passwd`, `passphrase`, `secret`, `secret_key`, `token`, `api_key`, `apikey`, `access_key` or `private_key`) before they write handoff files, the decisions list and recall output. A key value is masked only when it has 8 or more characters, is not only letters, is not only digits, and is not a call such as `get_secret(name)`. A secret in another shape (for example `sk_live_` keys, npm tokens or Slack webhook URLs) is not masked. A secret in prose with no key name is not masked. A PEM block with no END line is not masked. The model writes its own agent handoff file (`<sid>-agent.md`) with the Write tool, and a hook cannot mask that write. The hooks mask every copy that they make of it, but the original file can still hold a secret. The transcripts of Claude Code are not changed. See `SECURITY.md`.
- **Platform.** The nightly jobs (index and reconcile-and-prove, opt-in with `--nightly`) are macOS LaunchAgents. On Linux you add the printed cron lines yourself. Windows is not supported. The nightly self-test mentioned above is the canary. It ships in `tools/handoff-canary/` and is opt-in (`./install.sh --canary`, about $0.03-0.10 per run).
- **AI-graded evals.** Models wrote and graded the quizzes in this README, on one user's projects. Both benchmarks are code-graded. The 19% cost estimate is a single 4.7-day, one-user figure against a modelled counterfactual, not a bill.
- The nudge works only if the model obeys it. If the model does not obey, you still get the fresh summary, which is lossier than the handoff of the model.
- The fresh summary and the decisions update each run `claude -p --model sonnet` and use some of your quota (75 s and 100 s timeouts by default).
- The decisions list needs `fcntl` (macOS and Linux). It records only what you said in chat. It does not capture a decision that you never wrote or approved.
- The nudge reads the context size from the last usage entry of the transcript, so it lags by one assistant message.
- **Window source.** If `CLAUDE_CODE_AUTO_COMPACT_WINDOW` is not set, the nudge learns the window from past compactions, or uses 200,000 when there is no history. The nudge ignores a manual `/compact` (a boundary with trigger `manual`), because it happens at any context size. A learned window below 100,000 or above 2,100,000 is not used, and 200,000 applies. If the history comes from more than one model, the median can give a window between the models. The nudge keeps a learned value for up to 6 hours, so after a `/model` change the old window can stay for that time. Set the variable if you know your window.
- **Drift right after a compaction.** If reconcile runs in the 2 seconds after a compaction, it can show format drift until the next run.
- **Format drift alarm.** If Claude Code changes its transcript format, reconcile could count 0 compactions and 0 misses. So reconcile compares the post-compaction injects that the hooks recorded (main-session rows of `receipts.jsonl`) with the `compact_boundary` records of the same session. A session with 1 or more injects and 0 boundary records sets `format_drift: true` in `reconcile.json`. The affected `--prove` checks and claims then show `fail` with the reason `format_drift`, and `--check` prints one `format drift` line. A session whose transcript is deleted is skipped, so a deleted transcript does not raise the alarm.
- The order in which the three injected parts appear in context is not guaranteed. Each part names its number.
- **A session with no compaction adds no decision.** The decisions list grows only at a compaction. Run `/compact` before you close a session that made decisions. After `/clear`, the installer (0.21.0) injects the decisions list again.
- **Room for rules.** The three parts hold about 29,000 characters. Rules get full text first. When the rules use 90% of this room or more, `--check` says so; retire or merge rules (`recall.py decisions --kind rule`). A subagent gets the full text of the newest rules up to 4,000 characters, then one index line for each other rule.
- **Search levers.** Re-anchor runs only after a tool call, so a long reply with no tool call is not re-anchored; it uses a lock, so parallel tool calls inject once. The claim guard sees only its 12 cue phrases, and it ignores task notifications and compact summaries as user turns. The recall tool uses `CLAUDE_PROJECT_DIR` (else the working directory) to find the project.
- The strict recall rule (`--recall-rules`) and the recall MCP tool (`--recall-mcp`) make a search easier and more likely. They do not force one: the model can still skip it. No hook forces the model to run a recall search. The model chooses, so it can skip a search when it is wrongly sure. See [How Claude decides to use recall](architecture.md#how-claude-decides-to-use-recall).
- No hook forces the model to run a recall search. The model chooses, so it can skip a search when it is wrongly sure. See [How Claude decides to use recall](architecture.md#how-claude-decides-to-use-recall).
- The claim guard sees only wording. It looks for 12 cue phrases such as "as we decided". A reply that states an earlier fact in other words is not caught. A silent assumption, where the model states nothing about the past, is not caught either. A cue with no search is a signal, not proof: the model can be right.
- The claim guard is in shadow mode by default. It logs and changes nothing. Live mode (`HANDOFF_CLAIM_GUARD=block`) asks the model to continue once per user turn, and Claude Code stops such a loop after 8 continuations in a row. Read `claim-guard.jsonl` before you use it.
- Re-anchor repeats the rules, it does not make the model obey them. It adds up to about 4,000 characters of context each 50,000 tokens.
